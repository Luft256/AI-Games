30分・90秒の境界はPlaywright Clockで加速。実時間30分放置およびOSによる長時間バックグラウンド休止は未評価です。今回は各ゲームを独立した時計のブラウザcontextで検証しました。途中の共有contextで時計加速の影響を受けたカーゴ13個の結果は、自然終了の証拠から除外しました。

## COLOR CASCADE

評価URL: http://127.0.0.1:4316/AI-Games/games/color-cascade/
保存禁止環境の確認時には元サーバー停止後、同一worktreeのsiteを読み取り専用で4502ポート配信し /games/color-cascade/ へアクセスしました。
開始時は3,000点表示、再読み込み後は6,000点目標を評価しました。

- 無効交換: 1行1列の十字と1行2列のひし形を交換 → 「この交換では3つそろいません」、20手・0点のまま。最初の失敗でヒントを使う理由が分かります。
- 初回のヒントペア: 2行5列と3行5列 → 2連鎖、+270点。点線と選択表示で導入は理解できました。
- 別の盤面で、キーボードEnter→ArrowRight→Spaceによる2行3列/4列の交換 → 3個消し90点。6行2列/5行2列の交換 → 4個消し120点を予想どおり確認。
- 同一盤面を20手完走: 3,150点、最大2連鎖、6,000点に未到達。初回はヒント中心。
- 「同じ盤面」で再挑戦し、多く消せる手と2倍記号を優先 → 5,670点、最大3連鎖。即時点の選択だけでも差が出ました。さらに補充から連鎖を読む余地が残っています。
- 5手目・10手目・15手目に「次の5手は○が2倍」と表示され、残り手数とともに更新。
- 20手で結果表示、自己ベスト更新、再開を確認。途中の目標達成だけではラウンドが終わらないことも説明で分かります。
- 320px: 横幅320/scrollWidth320、tap交換が成功（1手で1,200点の連鎖）。マス約35×37px。Hでヒント2マス、Escで選択解除。
- 連鎖直後に30分相当へ加速 → TIME UP、1手・0点、保存済みbest5,670のまま。pending処理による加点なし。盤面aria-disabled=true、追加入力不可。
- localStorage getterがSecurityErrorを投げる環境でも20手完了（5,340点、最大4連鎖）、例外で操作停止なし。

改善案:
1. PCでは補充3記号が横並び、320pxでは縦並びです。「上の記号から」はPCで順番が曖昧です。表示方向に合わせ「左から／上から」、あるいは1・2・3の番号に統一。
2. 320pxのマスは約35px。入力は成功していますが、盤面外側の余白を減らす余地があります。
3. 強制モーダルの長いチュートリアルは不要。初回ヒントと短い説明で基本交換は理解できました。補充の「先頭→空いた列の一番下」を1例だけ示すと、連鎖を意図的に狙いやすくなります。

## CARGO SWITCH

評価URL: http://127.0.0.1:4197/AI-Games/games/cargo-switch/

- 練習開始後、丸の送り先に放置し、切り替えを遅らせる → 3個中1個成功、100点。結果に「分岐を通ったら次の記号に切り替えよう」と具体的な手掛かり。
- 練習再挑戦: 到着順の先頭に合わせ1→2→3を入力 → 3/3成功、360点。練習BESTは0のまま。
- 本番でH → 待避1回から0回、「1.6秒の間に到着順を確認」と表示。
- 独立contextで本番を開始し、到着順先頭だけに合わせキー入力 → 30/30成功、5,700点、100%、30コンボ、全便正しく到着の結果表示。STAGE 3まで進み、本番が自然終了。
- この1ラウンドでは予告された荷物を正しくルーティングでき、回避不能な誤配送なし。生成パターン全体での保証ではありません。
- 320px: 横幅320/scrollWidth320。倉庫ボタンをtapして練習3/3成功。
- 一時停止後、時計90秒相当 → 本番終了、未仕分け荷物の説明、0点。保存禁止環境でも例外なし。
- 練習を一時停止後30分相当 → SESSION EXPIRED、BEST0、途中記録は保存されないと表示。
- 初期PC画面の #practice は白背景に薄い文字で読みにくい問題を観測。最新版をreloadして修正確認: color rgb(38,57,47)、background rgb(255,255,255)。320px画面でも「3個で練習」が読めます。

改善案:
1. 文字色の問題は修正済み。
2. 到着順先頭にそのまま合わせれば全成功できました。2ベルトや4個予告に比べ、先読みを必要とする判断は少なめです。今の短いシフトは成立していますが、将来は待避の使い所・次に切り替える時点がスコアに影響すると戦略の幅が増えます。
3. 検証できた待避は初回消費のみ。各ステージでの回数補充は今回の実操作では未確認。

## RICOCHET RELAY

評価URL: http://127.0.0.1:4173/AI-Games/games/ricochet-relay/

- 部屋1、初期-12°で発射 → 0/2、残り2発。「次は1番、角度や鏡を調整」表示。点線を①→右壁→②へ合わせ、ArrowLeft13回で-25° → 2発クリア・銀。
- 部屋2、-48°で①→上壁→②→右壁→③ → 1発・金。
- 部屋3、M/Rで鏡Aを／へ回転、-39° → 鏡条件を満たし1発・金。
- 部屋4、-62° → 4リレー・3反射を読んで1発・金。
- 部屋5、鏡A／・B＼、-31° → 1発・金。
- 部屋6、鏡A／・B＼、-42° → ④の5反射条件を満たし1発・金。
- 全6室自然終了: 17/18点、金5・銀1。全室1発という再挑戦目標が分かります。
- 予測線と実際の経路は上記6室の成功に一致。ただし点線は2反射まで・ターゲットを通り抜ける幾何の予告です。後半は点線以降を自分で読む構成。
- 別の検証で②へ直接狙う → 「順番が違うリレーで光が停止」。そのまま3発使う → PULSES EMPTY、未来の番号へ触れた原因、同じ部屋で再挑戦のボタン。
- 部屋リトライ前29:00 → リトライ後29:00。時計はリセットされず、残り3発に戻る。
- 保存禁止環境で既知の解法を再確認 → 全6室18/18点完了、例外なし。reload後BESTは—。未保存環境で起動・完了できることを確認。
- 一時停止後30分相当 → TIME UP、全6室未完了の記録は保存されず、BEST—のまま。
- 320px: 横幅320/scrollWidth320、canvas248×186。tap角度指定・発射・鏡A/B回転・次室ボタンの操作だけで全6室18/18点を確認。

改善案:
1. 320pxでは条件ラベルが実寸約9.3px、鏡A/B名は約5px。canvasの描画に加え、各リレーの「②：1回反射＋鏡」などの条件を盤面下にHTMLで表示すると読めます。game.js 40行（鏡名）、45〜47行（番号・条件）。現状は操作不能ではありませんが、モバイルの理解に影響する改善点です。
2. 失敗ショットの実線と新しい点線が同じ色で残るため、調整中に前の光と予測線が重なります。失敗軌跡を時間で薄くするか、凡例を付けると読み分けやすいです。
3. 全金を取ると同じ6室の解法を覚えられます。初回の思考パズルとしては成立し、17→18の再挑戦は実証。無制限の長期再プレイ性は評価していません。
